# 第一阶段：运行链路监控

## 范围

第一阶段回答“Skill有没有稳定跑完、数据在哪一关被拦截、最终有没有一致交付”。业务运行代码位于 `scripts/runtime/`，监控实现位于 `scripts/monitoring/phase1/runtime_monitor.py`。

## 核心指标

| 维度 | 指标 |
|---|---|
| 任务 | 状态、耗时、失败数、错误阶段 |
| 来源 | 请求状态、延迟、条目数、新鲜条目数、解析成功数、缓存命中 |
| 漏斗 | 候选 → 时间通过 → 正文成功 → 相关性通过 → 日期通过 → 去重通过 → 写入 |
| 交付 | 飞书推送状态、网页发布状态、两端记录数一致性 |

每次正式运行生成唯一 `run_id`；文章按规范化URL生成稳定 `article_id`。监控数据进入 `data/monitoring.sqlite3`，可读报告进入 `data/monitoring/`。

## 失败策略

- 所有信息源均失败时，停止后续交付并将任务记为失败。
- 飞书与网页记录数不一致时，任务记为部分成功并阻断发布。
- 监控自身写入失败只记录告警，不影响业务主链路。

查看最近一次正式运行：

```bash
python scripts/monitoring/phase1/runtime_monitor.py
```
